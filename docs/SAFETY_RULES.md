# ZV-E10 实机操作 —— 硬性安全规矩

> 本文件是**约束**，不是建议。任何与实物机交互的操作都必须先对照本表。

## 🔴 规矩 0（最高优先级，用户 2026-10-25 明确下达）

> **任何时候不得覆盖 `/tmp/jiritsu/libJit.so`，也不得向相机写入新的 `.so`，
> 除非用户明确同意。**

**原因：** 2026-10 曾因向相机送入一个坏的 `dump.so` 导致变砖。
`.so` 是**可执行代码**，且 libJit 通道会在维护进程里 `dlopen` 它 ——
一个坏文件就可能在无恢复机会的位置执行。

**⇒ 现行做法：**
- 相机上**已有并验证可用**的 agent：`/log/agent_v14.so`（18,104 B，已在真机跑通）
- **通过 TCP 7777 的 RUN/PULL/PUSH 通道操作相机**，完全不碰 `.so` 写入
- 需要新载荷时，**先征求用户同意**，并在武装前走 `payload_guard` 预检

## 🔴 规矩 1：不写 `/etc`

```
✗ /etc/ld.so.preload        ← 当初变砖的直接原因
✗ 往 /etc 或 /tmp 写大文件   ← 二者与 /var 共用 12 MB (nflasha10)
```

**`/etc`、`/tmp`、`/var` 是**同一块 12 MB vfat 分区**（`nflasha10`）。
写满后 `/etc` 无法清理 ⇒ **不可恢复**。

## 🔴 规矩 2：不写 `/usr`

**`/usr`（nflasha15）默认以 `ext2 ro` 挂载 —— 直接写会失败，必须先
`mount -o remount,rw /usr`。**

> ### ⚠️ 更正（2026-11-02）：这条规矩的**理由**原先写错了
>
> 原文写的是「**`/usr` 是 LZP 压缩分区，写路径是空桩，所以改了也不生效**」。
> 这个说法**已撤回**：`qn06142/zv-e10-re` 原作者在
> [issue #4](https://github.com/cokeenet/zve10-qemu/issues/4) 里澄清，
> `/dev/nflasha15` 就是**普通未压缩 ext2**，remount rw 后写入**会持久化**
> （此前"LZP 压缩"的说法源自 `emmc.ko` 里**其它平台遗留**的休眠代码，作者已确认过时）。
>
> **规矩本身仍然保留**，但理由换成真实的那些：
> ```
> 1. /usr 里是被运行中进程 mmap 的库：覆盖/截断时空间不立刻释放，
>    O_TRUNC 截成 0 后写失败会留下半截文件（我们踩过，libObj.so 被弄成 13MB/21.3MB）
> 2. 改坏 .so ⇒ im.elf/appFw 起不来 ⇒ 相机变砖，且服务模式也可能一起没了
> 3. `/usr` 写入本身是持久的（普通 ext2），所以"改坏了会被记住"——
>    这比"重启就恢复"危险得多，没有可用回滚手段时不要动
> ```
> **⇒ 结论不变：能用"内存 bind / preload 钩子 / QEMU 验证"的，就不要动 `/usr` 落盘。**

## 🟡 规矩 3：允许的操作

```
✓ 只读：dd if=/dev/nflashaN、cat /proc/*、读 /log
✓ 写 /log（nflasha11，独立分区，剩余空间充足）
✓ 写 /setting（nflasha2，独立分区）
✓ mount --bind（运行时覆盖，重启即恢复）
✓ TCP 7777 的 RUN / PULL / PUSH
```

## 🟡 规矩 4：改动必须可回滚

| 改动类型 | 回滚方式 |
|---|---|
| `mount --bind` | 重启即恢复（天然）|
| `/log`、`/setting` 里的文件 | 删除即可 |
| **`.so`（禁止，除用户同意）** | **无天然回滚 ⇒ 必须预检 + 看门狗** |

## 🟢 恢复手段（按优先级）

| 情况 | 手段 |
|---|---|
| UI 异常（有 bind）| 等 90 秒 —— agent 看门狗自动 umount + 重启 |
| 想手动回原厂 | 断电重启 |
| 反复失败 | 放 `/log/zv1f_ui/safemode` ⇒ 永久拒绝武装 |
| 完全无响应 | 拔电池 |

## 会话纪律（踩过的坑）

**USB 侧：**
- 服务模式有**空闲超时**，send/read 分开做会在间隙断开
- `--keep`（留在服务模式）会让相机**卡在过渡态，甚至需要拔电池**
- **⇒ 所有 USB 操作必须在一次会话内完成，结尾发 `STOP_SENSER` 干净退出**

**网络侧（推荐）：**
- **`<CAMERA_IP>:7777`，毫秒级，不占用 USB 会话，无需插拔**
- 优先用网络通道做一切可做的事
