# 編譯與目錄說明

## 先執行不接相機的測試

需求為 Python 3.10 以上、`cc` 及 POSIX shell。公開測試使用 Python 標準函式庫，不需要 Pillow、NumPy、Sony 函式庫或相機。

```sh
python3 -m unittest discover -p 'test_*.py' -v
```

測試會在系統暫存目錄編譯 C 程式並執行。其中包含選單與觸控邏輯、合成設定快照、設定發布、原生回覆解析、派工協調及套件建置驗證。

公開設定快照由測試直接建立；私下研究用的實機 dump 與五個錄製回覆專用測試沒有打包。這不影響其餘合成回覆與失敗路徑測試的執行。

## 相機端編譯需要另外取得的輸入

相機端腳本使用 ARM hard-float 交叉工具鏈，並對某些 Sony 原廠 libc／monitor 做精確身分檢查。這些二進位資料不隨專案提供。不能拿主機的 glibc 或其他韌體版本替代，也不要把本地取得的原廠資料提交到 Git。

例如原生 UI 腳本的介面為：

```sh
sh host-tests/build_ui_trial3.sh build/ui /path/to/locally-obtained-camera-libs
```

這只是在開發電腦上編譯，不是安裝指令。預設有限時間的測試編譯，亦不等同研究中曾成功使用的所有持續運行參數。任何變更都要重新產生並核對對應的讀取器與模組釘選。

掃描器的建置需要本地 `host-tests/camera-mpr_monio.elf`；原生檔案轉接工具可透過第三個參數指定本地原廠 `mwf_monio.elf`。兩者都有雜湊檢查；檔案未提供或版本不符時，應停止編譯，而不是刪掉檢查。

## 為甚麼不能直接產生完整安裝包？

完整包還需要有合法再散布許可的 JPEG 效果 worker、相機端相容性驗證，以及尚未完成的整合驗收。公開版刻意沒有附上上游授權不明的引擎及其二進位檔。

套件組裝工具只負責驗證已提供的元件與雜湊，不會補齊缺少的引擎，也不代表產生的套件已獲實機認證。
