# 事故复盘：写错 LBA，把 M2 数据写进了 /system

> 2026-10-26。相机最终恢复正常。本文记录根因、为什么修了三次、真实危险边界，
> 以及已经落地的防护。

## 一、事情经过

```
1. 决定把 300 MiB 的 M2 hybrid 镜像刷进 /usr
2. 取 LBA 时抄了 n15_check.py 注释里的 "0x16C00"
3. 实际写入 40 块（2.5 MiB）后 fastboot 被 Darwin 电源 MCU 掐断
4. 以为坏了 /usr，于是"恢复"前 4 MiB —— 但用的偏移也是错的
5. 第二次"修复"又用了另一个错偏移
6. 相机一直闪 3慢2快，无法开机
7. 用多点内容匹配对全盘镜像反推真实分区表，才定位到真实错误
8. 用正确偏移写入 4 MiB，验证通过，相机恢复
```

## 二、三次错误的根因（层层叠加）

### 错误 1：抄注释而不是验算

```python
n15_check.py:
    PART_BLOCK0 = 0x2D800000 // 512             # 0x16C00    ← 注释错

实际: 0x2D800000 // 512 = 1,490,944 = 0x16C000
```

**代码是对的，注释是错的。我照抄了注释。**
**抄写时还丢了一个 0：`0x16C00` 比 `0x16C000` 少 4 MiB × 16 = 64 MiB 量级。**

### 错误 2：用累计和推算分区偏移

按 `/proc/partitions` 的 KiB 尺寸依次累加，得 nflasha3 起始 = 0xDF80。
**但分区之间有 64 KiB 对齐空隙，真实值是 0xE000。**

⇒ 恢复数据偏移差了 64 KiB，等于往 /system 写入**错位 64 KB 的整段数据**。

### 错误 3：忘了磁盘镜像与设备的 boot 区偏移

全盘镜像结构是 `[boot0 2MiB][boot1 2MiB][user area]`。

```
eMMC 偏移 = 镜像偏移 - 0x400000
```

我用内容匹配得到的 0x02000000 是**镜像偏移**，直接当成 eMMC 偏移用，
⇒ 又差了 4 MiB。

### 最终正确值

```
nflasha3  (/system)  eMMC 0x01C00000  LBA 0x00E000   48 MiB
nflasha15 (/usr)     eMMC 0x2D800000  LBA 0x16C000  300 MiB
我误写的位置          eMMC 0x02D80000  LBA 0x016C00
   ⇒ 落在 nflasha3 内偏移 18,350,080 (17.50 MiB)
```

## 三、为什么值得庆幸

| 对象 | 能否被写坏 | 结论 |
|---|---|---|
| **BootROM (mask ROM)** | **不能** | 芯片内 ROM，无法软件写入 |
| **boot0 / boot1** | **当前工具不能** | eMMC 独立硬件分区（镜像里偏移为负），LBA 寻址碰不到 |
| **分区表 (LBA 0~33)** | 能，但可恢复 | 只有 17 KB。写坏后 **BootROM fastboot 仍可用**（不读分区表），全盘镜像可恢复 |
| **任意分区文件系统** | 能，已全部备份 | 就是这次的情形 |

**真正的"完蛋"风险不存在：BootROM 不可写，而救援通道只依赖 BootROM。**
**但这次本可以更糟 —— 若 LBA 算到 0 附近，会抹掉分区表。**

## 四、已落地的防护

### 防护 1：写入前强制"地址证明"

`host/fb_partition.py` 新增：

```bash
python3 fb_partition.py write --lba 0x16C000 --image m2.img \
    --verify-target /root/fw/zve10_backup/nflasha15.img --target-offset 0
```

**写入前先读目标 LBA 的一个 64 KiB 块，要求它与参考镜像指定偏移**逐字节一致**；
不一致就**拒绝写入**并报出差异字节位置。**

**⇒ 这次的事故若用了这个参数，第一步就会被拦下。**

### 防护 2：分区表必须由内容匹配得出，不靠累加

已生成验证过的分区映射（多点探针匹配全盘镜像）：

```
分区        eMMC 偏移    LBA        大小
nflasha1    0x00010000   0x000080    7.94 MB
nflasha2    0x00800000   0x004000   20.00 MB
nflasha3    0x01C00000   0x00E000   48.00 MB
nflasha5    0x05800000   0x02C000   60.00 MB
nflasha6    0x09400000   0x04A000   16.00 MB
nflasha7    0x0A400000   0x052000    8.00 MB
nflasha12   0x2AC00000   0x156000   40.00 MB
nflasha13   0x2D400000   0x16A000    4.00 MB
nflasha15   0x2D800000   0x16C000  300.00 MB   ← /usr
nflasha23   0x50800000   0x284000   64.00 MB
nflashaB0   (boot0)      —           2.00 MB
```

### 防护 3：写前必须先用 verify 证明写通路

```
write 之前先跑 verify（读→原样写回→再读→比对）
```
**这次做对了这一步（CMD25 多块写就是这样验证的），只是地址错了。**

## 五、经验教训（写给以后的自己）

1. **文档里的数字一律验算，注释不可信。**
2. **分区偏移必须用内容匹配 + 多点探针，禁止用累计和。**
3. **镜像偏移 ≠ 设备 LBA，中间隔着 boot 区，必须显式换算并验证。**
4. **每次写入前，先读目标区域并与参考比对 —— 这就是"地址证明"。**
5. **出问题后先采集证据（读相邻未写区域反推对齐），不要连猜三版修复。**
6. **写入粒度是 64 KiB ⇒ 任何"再靠近一点"的错误都可能覆盖 64 KB。**
7. **fastboot 会话可能只有几秒 ⇒ 恢复动作要提前编成脚本，一条命令跑完。**
