## 三、可能的原因（按可能性）

### 原因 A：bootin 重启导致 Wi-Fi 重新初始化（最可能）

```text
bootin 是 pid 149 常驻进程，它管理 im.elf 以及一部分启动期子系统。
杀掉它 + 重新执行，很可能连带重启了网络初始化流程
⇒ 相机 Wi-Fi 需要重新关联（通常 10-30 秒）
⇒ 但已经等了 3 分钟以上没回来
```

### 原因 B：im.elf 没起来 ⇒ 相机进入"无 UI"状态，Wi-Fi 也随之停

```text
im.elf 是 UI 主进程。它不在时，相机可能：
· 屏幕黑
· Wi-Fi 服务（pump/wpa_supplicant）继续跑但没人管理 SSID
· 相机可能进入保护状态
```

### 原因 C：相机重启了

```text
我们之前的观察：杀掉 im.elf 后如果手动启动失败，相机会自行重启
（上次就是这样，uptime 从 1226 掉到 37）
⇒ 如果这次也重启了，Wi-Fi 应该会重新起来
⇒ 但没起来 ⇒ 说明可能不是重启
```

## 四、当前相机侧的持久化状态（关键，决定能否自愈）

```text
/setting/mode/dmode   = "3p"
/setting/mode/preload = "/usr/tool/LeakTracer.so:/log/menu_ui.so"
/log/nm-menu-stage    = 1
/log/menu_ui.so       存在（10,500 B，sha ad2665e7…）
```

   ⇒ stage=1 只调两个只读函数，理论上不会崩
   ⇒ 所以"重启后应该能自愈"**
